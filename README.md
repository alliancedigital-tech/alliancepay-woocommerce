# Платіжний шлюз AlliancePay для Wordpress + WooCommerce

![AlliancePay Logo](https://alb.ua/_next/static/media/Alliance_logo.25cb4c66.svg)

## Огляд
Офіційний модуль платіжного шлюзу **AlliancePay** для **Wordpress + WooCommerce**. Цей модуль дозволяє безперешкодно інтегрувати AlliancePay у ваш інтернет-магазин, забезпечуючи безпечний, швидкий та надійний процес оплати для ваших клієнтів.

## Основні можливості
* Безпечна обробка платежів через API AlliancePay.
* Підтримка різних валют та методів оплати Visa/Mastercard/GooglePay/ApplePay.
* Автоматична синхронізація статусів платежів (webhook / callback).
* Просте налаштування та зручний інтерфейс в адмін-панелі.

## Вимоги
* PHP 8.0 або вище
* PHP розширення: gmp, hash, openssl, sodium
* Wordpress версії 6.5+ & WooCommerce 10.1.0+
* Активний обліковий запис мерчанта AlliancePay.

## Фіскалізація (v1.9.0)

Фіскалізація успішних платежів (PURCHASE) і повернень (REFUND) разових замовлень через Alliance Kasa.
Рекурентні платежі підписок **не** фіскалізуються. Підтримуються замовлення лише в UAH.

### Налаштування (AlliancePay → Settings → «Фіскалізація»)
- **Увімкнути фіскалізацію** — без цього запити не надсилаються, блок і поля товару приховані.
- **Автоматична фіскалізація** — після успішного платежу/повернення запит надсилається автоматично (після відповіді callback-у, помилка не ламає платіж). Вимкнено — лише кнопка «Фіскалізувати» в замовленні (і для платежів, і для повернень).
- **Дефолти**: код податкової групи (`taxCode`), УКТЗЕД (`classificationCode`, обов'язковий при `taxCode` 2, 7, 8), акцизні марки (`exciseLabels`), код одиниці виміру (`measurementCode`, за замовчуванням `0001`).

### Поля товару
Вкладка «General» товару та кожна варіація (поля «AlliancePay: фіскалізація»). Порядок вибору значення для кожного поля окремо: варіація → батьківський товар → дефолт із налаштувань → поле не передається.

### Як працює
1. Платіж SUCCESS → запис у `alliance_fiscalization` зі статусом `PENDING` → callback `…/wp-json/alb/v1/fiscalization-notify` (JWS) → `SUCCESS` (ФН, посилання на чек) або `FAIL`.
2. Позиції формуються з фактично сплачених сум (після знижок), доставка і збори — окремі позиції; залишок округлення додається до останньої позиції. `unitPrice` передається в гривнях (float, напр. `120.00`), а не в копійках; Σ(count × unitPrice) = сумі операції.
3. Повернення: позиції беруться з об'єкта повернення WooCommerce; повернення «лише сумою» розподіляється пропорційно позиціям замовлення.
4. Запит ідемпотентний за `operationId`; кнопка «Оновити статус» повторно надсилає той самий запит.
5. Локальний статус `ERROR` — помилки 400/5xx/таймаут/підпису; тоді доступна кнопка «Фіскалізувати».

### Типові помилки
`missing_required_field`, `invalid_format` — перевірте поля товару/дефолти; `payment_not_found` — операцію не знайдено; `original_receipt_not_found` — спочатку фіскалізуйте покупку; `541` — помилка підписання на стороні Alliance Kasa.
Логи: `wp-content/uploads/alb-logs/fiscalization.log` (ключі, підписи та JWS маскуються).

### Ручна перевірка (автотестів немає)
Чиста установка та оновлення зі schema 7 (таблиця, `measurementCode=0001`); оплата → PENDING → callback → SUCCESS; повне й часткове повернення → REFUND; авто вимкнено → тільки кнопка; невалідний JWS → 400; товар зі змішаними значеннями (частина з товару, частина з дефолту); варіація без значень → батьківський товар.
